# PokerNow Algo Bot

[English README](README.md) · [Релизы](https://github.com/gcof/PokerNowAlgoBot/releases) · [Изменения](CHANGELOG.md)

Локальное расширение Chrome/Edge для **No Limit Texas Hold'em на PokerNow**. Рассчитывает эквити против эвристических диапазонов соперников, объясняет решения и по выбору выполняет ходы. Работает на HTTPS-страницах столов обоих доменов PokerNow. Конкретные столы, аккаунты и ники в коде не заданы: своё место определяется по маркеру `.you-player` самого сайта.

Применяй там, где автоматизация разрешена площадкой и участниками. Диапазоны заданы вручную; качество игры и винрейт экспериментально не подтверждены.

## Установка и запуск

1. Скачай архив `pokernow-algo-bot-vX.Y.Z.zip` из опубликованного релиза и распакуй.
2. Открой `chrome://extensions` или `edge://extensions`, включи режим разработчика.
3. Нажми «Загрузить распакованное расширение» и выбери папку с `manifest.json`.
4. Обнови вкладку PokerNow и займи место. Панель появится справа сверху.

Если скачал исходники репозитория, выбирай папку **`extension/`**. Установка не требует Node.js, сервера или API-ключей. После обновления исходников перезагрузи расширение и вкладку стола.

Изначально включён режим **«Только расчёт, без ходов»**: «Запустить» выводит рекомендации без кликов. Для автоигры сними галочку и нажми «Запустить». Перед ходом добавляется случайная пауза 1–2 секунды, после неё состояние стола проверяется повторно.

**«Стоп» или Esc** отменяют ожидающий ход. Смена режима или стола инвалидирует решение. «Возобновлять после обновления этого стола» — отдельная настройка, выключенная по умолчанию. Настройки хранятся по адресу стола. После пересадки появляется новая панель либо сбрасывается текущая; новый стол первоначально остановлен в режиме расчёта. На одном столе/домене автоигру запускает только одна вкладка через Web Locks. Без этого API доступен режим расчёта.

Браузер и компьютер должны оставаться включёнными. Вход в аккаунт, посадка, регистрация в турнире, покупка фишек, снятие Away и восстановление соединения сайта выполняются пользователем.

## Алгоритм

Учитываются позиция, цена колла, эффективный стек, структура борда, дро и наблюдавшиеся действия. Диапазоны сужаются после агрессии, сохраняя ненулевой вес слабых комбинаций. Для вэлью-рейза отдельно оцениваются руки продолжения. Повторные повышения требуют более сильного преимущества.

Обычно выполняются 2600 симуляций, против более чем трёх соперников — 1200. На ривере против одного соперника перебираются все допустимые комбинации его диапазона. Карты в выборке не пересекаются. Учитываются погрешность Монте-Карло и приближённая реализация эквити; при колле олл-ина позиционная скидка не применяется. Сумма ставки проверяется по допустимым значениям PokerNow перед отправкой.

Поддержаны анте, фишки/BB, All In, игроки в пасе и быстрая кнопка ставки с CSS-классом `call`. Для перевода BB в фишки нужен большой блайнд в фишках в шапке стола.

Нет ICM, модели выплат, сбалансированной частоты блефов, обучения соперникам между раздачами, полноценной реконструкции исторических сайд-потов, Omaha и нескольких бордов. Быстрые действия между наблюдениями могут быть пропущены. Неполная история отмечается, рассинхронизация вызывает ожидание нового наблюдения. Точный перебор ривера точен только относительно принятого диапазона; погрешность симуляции не измеряет ошибку модели. Изменения интерфейса PokerNow могут потребовать обновления адаптера.

## Приватность и разработка

Разрешение — только `storage`, область работы — страницы столов PokerNow. Серверов, телеметрии и скрытых API нет. Читаются свои видимые карты и общий борд. Настройки хранятся локально; журнал и история — в памяти. Идентификаторы участников используются во время работы без привязки к определённому аккаунту в исходниках. Перед отправкой материалов в Issues убирай ники, ID и ссылки-приглашения.

Для разработки нужен Node.js 24+, внешних пакетов нет:

```sh
npm run check
npm test
npm run build
npm run benchmark
```

Команды без npm и структура проекта описаны в [основном README](README.md#development). Сборка создаёт ZIP и `SHA256SUMS` в `dist/`, исключая личные материалы. Версии пакета, манифеста и тега `vX.Y.Z` должны совпадать. Отправка тега запускает проверки и создаёт черновик GitHub Release с архивом; сопровождающий проверяет и публикует его.
